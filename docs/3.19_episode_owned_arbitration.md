# AIVD 3.19 — Episode-Owned Epistemic Arbitration

## Research question

Can AIVD discover previously reachable unknown security behavior more
effectively when the global arbiter owns the **episode** after a single infra
smoke, rather than inheriting leftover slots after sequential residual-sweep
and gate-reserve peel?

This is still not a new vulnerability-discovery algorithm. Budget stays **32**.

## Diagnosed 3.18 remaining bottleneck (not retuned against Holdout-18)

3.18 put a completion-value arbiter **inside leftover**. Sacred Holdout-18
first-run stayed `NOT_DISCOVERED`:

- smoke (1) + residual sweep (4) ran before the arbiter
- 8 slots locked for gates that never ran if discovery failed
- leftover ~9 tested candidates; delayed closer never entered representation
- isolated `EpistemicController@32` verified the same holdout at rate 1.0

That is outer-pipeline peel, not greedy-EIG scoring and not a closed lexicon.

## Architecture (3.19)

`full_3_19` / `epistemic_full` / `arbiter`: **episode-owned**.

```
INFRA SMOKE (1, quota only)
  → GLOBAL ARBITER owns remaining slots
      residual / invention / open-world / axis propose
      one experiment per step
  → if a positive candidate exists, remaining slots go to gates
```

`full_3_18` is unchanged leftover-arbiter so the 3.18 protocol stays reproducible.
Default `epistemic_mode=off` ≈ 3.17.

No holdout-specific tokens, mechanism names, or rules. No budget inflation.

## What 3.19 does not do

- Does not overwrite the 3.18 Holdout-18 sacred first-run (`NOT_DISCOVERED`)
- Does not retune scoring weights after seeing Holdout-18
- Does not special-case X–W or Holdout-18
- Does not restore 3.17 XOR grammar priority (OW-3 remains an honest miss)
