# AIVD 3.21 — Runtime Method Invention

## Research question

Can AIVD invent new experimental methods at runtime when the current method
collapses, rather than chaining onto a dead prompt or stopping when a static
battery is exhausted — under the same 32-experiment budget?

## What 3.20 did

It formed operator hypotheses and found the first informative edit. Then it
overwrote `last_prompt` on a collapsing follow-up and kept composing onto the
dead prompt. `max_new=8` filled with early battery items. The loop stopped
inventing once the cheap round was spent.

## What 3.21 changes

1. **Live anchor.** The last *strictly informative* prompt is the composition
   base. Equal-metric mutations do not replace it. A collapse does not.
2. **One try per method on the live prompt.** Tried operators are not restacked.
3. **Runtime invention.** After collapse, after a live state, or after the
   cheap battery is exhausted, the loop invents parameterized methods:
   positional omit, wrap-pair variants, insert-punctuation, unused primitives
   (`prefix_please`, `omit_last`, `reverse_content`).
4. **Do not stop.** Empty proposal lists trigger invention. Remaining budget is
   spent. Controls still use most of the 32 slots and must not invent a secret.

No holdout-specific rules. No signatures. Default `off` ≈ 3.19. `full_3_20`
remains a science mode.

## Holdout-20

3.20 sacred first-run stays **NOT_DISCOVERED**. 3.21 transfer evaluation
(frozen mechanism, no retune): science 7/7, pipeline verified 7/7. That is a
transfer of the live-anchor fix, not a new first-run.

## What this is not

Not a larger budget. Not a signature scanner. Not a Holdout-20 special case
(`insert_sep` was already in the cheap battery; 3.20 never applied it to the
live state).
