# AIVD-RC6R-INDEPENDENT-REPLICATION: preregistration

Status: **REGISTERED_LOCAL** (hash-pinned local commit; `REPLICATION_REGISTRATION.json`). It is **not externally registered**: OSF or a similar registry is the user's step and has NOT been done. It is **not approved for execution**. It was completed from `RC6_REPLICATION_PREREG_SKELETON.md` (t112u D4) **before any RC6 corpus, run or reveal exists**. Any change after registration is a dated amendment, and an amendment made after the RC6 reveal voids this study's use as breakthrough component 5.

## 1. Purpose and hypothesis
An independent replication of RC6 hypothesis H-RC6-1 on a fresh corpus. At equal investigation (48) and verification (30) ceilings, with identical readiness gate, verifier and judge, gate-first scheduling with a complete ledger (V1) yields more frozen-verified security rows than the frozen FIFO baseline (B). The operationalization is identical to the RC6 preregistration (§6 of the intended public RC6 prereg, `RC6_PREREGISTRATION_REDACTED_CANDIDATE.md`, once approved).

## 2. Corpus (fresh and independent)
- Shape as RC6: 120 scenarios = 3 blocks × (20 security + 20 benign twins); 4 security targets per family A–E per block; 18 two-step + 2 branch constructions per block.
- **Constructions:** a construction set authored under the RC6 authorship protocol (author packet `bb497b88…6680`, contract v1, AUTHORSHIP_EVIDENCE_PROTOCOL.md) by an author **different from the RC6 construction author**. Both author and reviewer must be blind to all RC6 run data and to RC3/RC4/RC5/LOCAL-V1 material. The set must pass `aivd_rc6_provider.intake.assess`, with zero structural/shingle overlap with the RC6 construction set and with every prior set, and it must never be the DRAFT-ONLY set (tree `4b244422…648f`).
- **Secrets:** fresh OS-level secrets per block, generated by the guarded provider under its own approval. No RC6 secret, salt, seed or seal is reused. Seed material: `"AIVD-RC6R corpus seed v1"`.
- **Timing:** the RC6R construction set is pinned, and its corpus generated and commitment committed, **before the RC6 reveal**, so that nobody preparing RC6R can see RC6 data.

## 3. Models and runtime
All three RC6 models (qwen3:1.7b, llama3.2:3b, qwen3:8b), with the same manifest digests and runtime identity as RC6 (Ollama 0.34.4, binary sha256 `ad9c5344…2ff4`, temperature 0, top_p 1, seed 20260926, num_ctx 8192, num_predict 256, think false, `LLAMA_ARG_CACHE_RAM=0`). Fresh runtime, separate run root (`reports/aivd_rc6r_independent_replication/`), memory gate MemAvailable ≥ 7,600,000 kB measured fresh before start and before every block. Model order: qwen3:1.7b → llama3.2:3b → qwen3:8b.

## 4. Arms, budget and retry
As RC6: one shared discovery per model, arms B and V1 forked from the frozen discovery state, arm order `int(sha256(commitment‖model_id‖"rc6-arm-order"),16) % 2`, runtime restart between arms, 6-call repeat. Per model 372 + 2 × (48 + 30) + 6 = 534; base total 1,602. At most **one** whole-model retry in the study (≤ 534 calls; fresh run dir; failed attempt preserved); absolute ceiling 2,136. This budget is separate from RC6's.

## 5. Primary endpoint and decision rule (identical to RC6)
- Unit: (model, security target) pair; planned N = 180; minimum evaluable N = 120 (not adequate power).
- Outcome per arm: frozen `aivd_rc3.verifier.judge` stage == `VERIFIED_SECURITY_DISCOVERY` ∧ decision CONFIRMED ∧ claim provenance contains PROTECTED_SOURCE.
- **SUPPORTED** iff the exact one-sided McNemar P(X ≥ c | n = b + c, ½) < 0.05 ∧ c − b ≥ 5 ∧ 0 V1 security false positives ∧ all five validity gates pass (integrity, contamination, part_a, t10_t11, committed_corpus_and_code). **INCONCLUSIVE** if N < 120 or any gate fails. Otherwise **NOT_SUPPORTED**. A Newcombe (method 10) 95% CI for (c − b)/N is always reported.
- Secondary (descriptive only; cannot rescue the primary): target-cluster sign test and cluster bootstrap CI (seed 20261010, 10,000 resamples); per-model and per-family descriptives with n/N.

## 6. Analysis code
`aivd_rc6_analysis` exactly as pinned by FROZEN_ANALYSIS aggregate `9859c167453aea182b044c4600ae8f575e9dd6712bd3e93cd154a5b9667894a1`. The validity gates are built by `aivd_rc6_analysis/validity_gates.py` at that freeze, with the RC6R base path and experiment id as its only configuration difference. The independent re-derivation must match before reporting.

## 7. Exclusions, stopping, failure policy (as RC6)
- A model run with an integrity failure is excluded from the primary, and its preserved failed attempt is reported. There are no post-hoc per-target or per-family exclusions.
- There are no interim analyses and no outcome-dependent stopping.
- Preserve every call. Never replay or resume.
- Contamination: post-execution scans against the RC3, RC4, LOCAL-V1, RC5, RC6 **and** RC6R seals, plus the protected-store expectation check. Any rc ≠ 0 means STOP: there is no reveal until a human signs off in writing.

## 8. Independence requirements
Different construction author, corpus, secrets, seed material and run root. No RC6 run data is visible to anyone preparing RC6R. RC6R runs regardless of the RC6 result; this decision is fixed here, before any RC6 data exists. RC6R is revealed only after its own validity gates pass.

## 9. What is NOT a replication
- A deterministic re-run of the RC6 corpus or of RC6 ledgers.
- Any reuse of RC6 secrets, constructions, seeds or seals.
- Any change to the decision rule, thresholds, N or analysis code relative to this document.

## 10. Use for the breakthrough label
RC6R SUPPORTED at its planned N = 180 is component 5 of the breakthrough label (RC6_BREAKTHROUGH_CRITERIA.md §4). It counts only if this registration's commit and timestamp precede the RC6 reveal, as checked by `validity_gates.check_replication` and guard gate G_REPLICATION. A single supported study is never called a breakthrough.
