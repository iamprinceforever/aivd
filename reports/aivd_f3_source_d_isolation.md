## What was built

Five logical roles share one interpreter. That is `LOGICAL_ONLY_SEPARATION`. The discovery object receives a token and a public ledger. Decrypt and the verifier result reject that token. The key is not on the ledger. This is an API boundary, not a machine boundary. Any code in this process can import the vault. That attack is not fixed. The claim evaluator therefore does not return `SOURCE_D_READY` for this process.

The seal is HMAC-SHA256 in counter mode, then a second HMAC. A plaintext hash is refused. The nonce is derived from the key and the plaintext commitment, so the same fixture and the same key repeat. The plaintext commitment stays inside the ciphertext. The public ledger stores the ciphertext commitment and an opaque handle. Handles sort the corpus. A label is not an input to that sort.

One schema failure rejects the whole list. The schema checks shape. It does not decide whether a relation holds. After discovery locks, the verifier decrypts, recomputes the two frozen relations from the sealed pairs or the sealed policy, and only then compares that result with the sealed provider bit. A mismatch is `CORPUS_INTEGRITY_FAILURE`. The discovery token cannot read it.

The scanner looks for the historical marker strings. A clean scan leaves history isolation `NOT_VERIFIED`. This process sits inside the AIVD tree, so its own environment snapshot is `SOURCE_D_INVALID`. No provider history was recorded, because no provider was called.
